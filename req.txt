Lab 2: Product Listing, Navigation & Form Validation with Next.js
Class SE20B.NJS  |  Practical exam  |  10 points  |  Deadline: ______________
1. Objectives
Extend your Lab 1 project (same GitHub repository, same Vercel project) with a product list Home page, client-side navigation and form validation.
Practise Tailwind CSS and ShadCN UI, reusable React components, and React state (useState) in Next.js.
This lab is UI only: no database, API or real authentication is required.
Important change from Lab 1: the Home page / is now the product list. The login form you built in Lab 1 moves to /login.
2. Requirements
2.1 Technical
Next.js (App Router) with Tailwind CSS. Initialise ShadCN UI (npx shadcn@latest init) so that components.json exists in the project root.
Use at least two ShadCN components from components/ui/ (for example Button, Card, Input, Label) and import them in your pages/components.
Forms are client components ("use client") and keep their values and error messages in React state (useState).
2.2 Home page (route /)
A header with a Login button and a Register button.
A product grid with at least 6 products. Each product is shown as a card with: name, image, description and price (currency symbol + number, e.g. $19.99).
Product data is static: keep the array (or JSON) in a separate file such as data/products.ts (or under lib/), not written inside the JSX.
Create a reusable component named ProductCard (file components/ProductCard.tsx or .jsx, src/ allowed) and render the list with .map().
Every product image must load and have an alt text. Keep images in public/ (recommended) or, if remote, configure images.remotePatterns in next.config.
2.3 Navigation
Clicking Login goes to /login; clicking Register goes to /register.
Use client-side navigation (next/link or useRouter). A plain <a href> that reloads the whole page is not accepted.
2.4 Login (route /login) and Register (route /register) forms
Add noValidate to the <form> so that your own messages are displayed instead of the browser's built-in pop-ups.
Validation runs when the user clicks the submit button (or presses Enter). No error is visible when the page first loads. An error disappears once its field is valid.
When all fields are valid, show a success message (no real login/registration). Use the exact texts and messages in the tables below.

4. Design
Any colour palette, but the UI must be clean, consistent and user-friendly. Use a card-based layout for products (ShadCN Card is recommended).
Responsive: at 375 px width there is no horizontal scrolling and products are in 1 column; at 1280 px width products are in at least 3 columns.
All product images have the same size/aspect ratio; text does not overflow or overlap.
